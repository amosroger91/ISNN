# Sports newsroom research and data

## Which sources should power the first edition?

### Takeaway

Make NBA the first structured beat while production proves itself. Use one rights-cleared structured feed for machine-readable game facts, official league/team records for verification, an independent original-reporting source for context, and Isaac for the editorial angle. Build provider-neutral adapters so MLB and NFL can follow without requiring that all leagues and media rights arrive together.

### Cited Findings

- NBA publishes its current season schedule, individual game entries, statistical definitions/leaderboards, and an official dated injury report. The injury report changes on its own schedule and is evidence of an announced status as of that issue, not proof of diagnosis or future availability. Team game notes can be an official audit source for a given team's claimed milestones. [NBA schedule](https://pr.nba.com/2026-27-nba-regular-season-schedule), [NBA games](https://www.nba.com/games), [NBA statistics](https://www.nba.com/stats), [NBA injury report](https://official.nba.com/nba-injury-report-2026-27-season/), [Example NBA team game notes](https://www.nba.com/gamenotes/kings.pdf)
- NBA's partnership names Sportradar as its exclusive data provider worldwide, with a separate distinction for live game video distributed to international betting operators. Its NBA API documents `Daily Schedule`, complete regular/postseason play-by-play coverage, box scores/summary, game-state transitions, and change logs. Use `coverage` flags for preseason and unsupported data. Its endpoint reference specifies current-day log cache and publishing intervals; a separate integration page gives different timings, so read response headers, verify against the contracted endpoint, and poll based on actual freshness and budget instead of hardcoding either. [NBA announcement](https://pr.nba.com/nba-sportradar-global-partnership), [NBA API game status](https://developer.sportradar.com/basketball/docs/nba-ig-game-status-workflow), [NBA summary API](https://developer.sportradar.com/basketball/reference/nba-game-summary), [NBA change log API](https://developer.sportradar.com/basketball/reference/nba-daily-change-log), [NBA integration guide](https://developer.sportradar.com/basketball/docs/nba-ig-live-game-retrieval)
- NFL.com's Game Center provides a human-reviewable official game-book PDF from the recap. Official injury reports distinguish practice and game status. Genius Sports and NFL's newer joint release extends exclusive official real-time play-by-play and proprietary Next Gen Stats distribution to media through the 2029 NFL season. A league announcement with an earlier endpoint is superseded. [NFL game books](https://support.nfl.com/hc/en-us/articles/35869678028180-Game-Books), [NFL injury report](https://www.nfl.com/injuries/), [Genius Sports and NFL latest extension](https://investors.geniussports.com/news/announcements/announcements-details/2025/The-National-Football-League-Expands-and-Extends-Strategic-Partnership-with-Genius-Sports-in-Multi-Year-Deal/default.aspx)
- MLB publishes official scoreboard, transactions, Baseball Savant game and historical query surfaces, and Statcast definitions. MLB/Sportradar extended their exclusive official data partnership through 2032. The corresponding 20-F distinguishes the official data distribution from audiovisual distribution for international sports betting clients. Do not infer an editorial-video grant from this data announcement. [MLB scores](https://www.mlb.com/scores), [MLB transactions](https://www.mlb.com/transactions), [Statcast search](https://baseballsavant.mlb.com/en/statcast_search), [MLB Statcast glossary](https://www.mlb.com/glossary/statcast), [MLB/Sportradar joint release](https://investors.sportradar.com/news-releases/news-release-details/major-league-baseball-and-sportradar-announce-expanded-exclusive), [Sportradar annual report](https://investors.sportradar.com/static-files/7970b93a-65b7-4f3f-a176-80a01c95ef2f)
- SportsDataIO publishes NBA, NFL and MLB API specs and commercial licensing information. It can supply schedules/scores, deeper stats/play-by-play depending on product, scoped derived analytics, commercial display inside the licensed product, and caching. Approval is still specific to inputs, outputs, and feed inventory; its FAQ discusses attribution and post-termination retention as negotiated, and separates commercial use from its personal Discovery Lab. Obtain a written order form for the YouTube use, not just a sales statement about general media customers. AP’s Media API carries contract-entitled original sports reporting and permitted assets. AP is an independent reporting source only where AP originates the corresponding reporting. Public AP links can be research leads but never a license for wire scripts or packaged assets. [SportsDataIO licensing FAQ](https://sportsdata.io/help/data-rights-and-licensing-questions), [NBA API](https://sportsdata.io/developers/api-documentation/nba), [NFL API](https://sportsdata.io/developers/api-documentation/nfl), [MLB API](https://sportsdata.io/developers/api-documentation/mlb), [AP sports licensing](https://www.ap.org/content/topics/sports/), [AP Media API](https://api.ap.org/media/v/docs/Getting_Started_API.htm)
- Public site restrictions differ. NBA’s statistics section allows legitimate news reporting with prominent attribution and separately restricts commercial identification, comprehensive regularly updated stats databases, and archived play-by-play depictions. NFL’s site terms require consent for systematic retrieval and commercial use; MLB site terms restrict automated scripts and unauthorized reproduction/derivatives/displays. Operationally use those pages as human/editor verification links, and turn a domain into a machine-ingested adapter only via a permitted source-specific interface and use. SportsDataIO commercial terms depend on signed scope; Sportradar’s published Official Media Data Addendum describes non-commercial media/editorial uses, limitations on promotions and commercial uses, and requires express approval for new derived data points. Procurement must confirm or obtain specific exceptions in writing for public monetized YouTube, channel(s)/territories, graphics and VO display, thumbnails/Shorts/archives, data storage/retention, calculated stats, AI subprocessors and attribution. No contract exists in evidence for Overtime Desk. [NBA terms §9](https://www.nba.com/termsofuse), [NFL terms §1.3](https://www.nfl.com/legal/terms/), [MLB terms](https://www.mlb.com/official-information/terms-of-use), [Sportradar media addendum](https://developer.sportradar.com/sportradar-updates/page/official-media-data-addendum), [SportsDataIO licensing](https://sportsdata.io/help/data-rights-and-licensing-questions)

### Inferences

- Recommend evaluating Sportradar NBA for authoritative canonical identities and correction workflows, and asking SportsDataIO for a scoped alternative if written display, public archive, cost, and derived-rights terms fit better. Run a 7–14 night fixture/shadow comparison on completeness of finalized games, detection lag for changes, field-level quality, runtime limits and total cost; no second paid live feed is necessary at launch. Two data vendors that both originate at league scorers are corroboration of a feed discrepancy, never two independent sources for contested reporting. Anchor NBA work to the current season's regular-game volume, with the option to pivot real footage pilot to a community/club program if NBA footage rights are unavailable. MLB next when in season (pitch sequences and Statcast lend themselves to charts). NFL can remain a manually verified news beat before a structured weekly game package is warranted.
- Classify evidence. For official routine results or published schedule, one cited league original or entitled contract feed suffices. Official stats must carry game/entity IDs, period, units, measurement definition, and `asOf`; quoted statements require transcript/timecode and actual words. For consequential/contested claims, require primary named/on-record evidence and a second independently originated report or withhold. Official statement confirms “team announced X”, not the truth of claims quoted inside it. Trade agreed vs finalized, expected vs confirmed, questionable vs ruled out, and injury status vs medical diagnosis are distinct. Anonymous/social claims are a lead; keep rumor out of unattended scripts, graphics, thumbnails and titles. An authenticated league/team post can lead to its official announcement; verify authorship and authority.

### Gaps

- Confirm actual budget, channel monetization, first league Isaac wants, contractual scopes, provider latency/quotas, whether AI inference is allowed, and whether any rights already exist. Pricing or specific terms of a customer offer cannot be inferred from public docs. Separate delivery feed rights from clips, league branding, music, and graphics template rights. Treat an unavailable contract as a visible integration blocker while building the fixtures, operator ingestion and chart fallback.

## How does the application become a newsroom?

### Takeaway

Separate continuous collection, normalized event history, story selection, evidence-bound script generation, and copy review. Every aired factual sentence, chart, score bug, title, and thumbnail should have resolvable evidence in an edition-level manifest. Preserve Isaac's exact take and review of the changed cut.

### Cited Findings

- Today `researchEdition()` samples up to 40 normalized RSS items from recent articles using a 36-hour filter and assigns 1–4 stories. `writeEpisode()` uses linked excerpts and Isaac's attributed take, validates cited numbers against tokens present in sources, and calls a model audit. Sources, editing, chat, and the same-revision render guard already exist. Tests mock provider traffic. Keep those compatibility entry points, upgrade their internals, and leave The Word Daily independent. [Research module](../../server/sports/research.mjs), [Edition lifecycle](../../server/sports/desk.mjs), [Sports routes](../../server/sports/routes.mjs), [Research tests](../../test/sports-research.test.mjs)
- AP describes independent corroboration, visual metadata/date/location checks, confirming ownership and permissions for user-supplied visuals, publicly labeling corrections, and human editorial responsibility even with AI research/extraction support. Use these standards as precedents for our verification and disclosure design. [AP verification practices](https://www.ap.org/verify), [AP corrections and attribution](https://www.ap.org/about/news-values-and-principles/telling-the-story/), [AP 2026 AI newsroom standards](https://www.ap.org/the-definitive-source/announcements/ap-updates-newsroom-standards-for-artificial-intelligence/)
- Current xAI documentation supports bounded Web Search domain allowlists, X Search handle/date limits, source annotations, and structured outputs for applicable Grok models. A tool source list can include sources merely encountered, and inline citations are voluntary. A Grok implementation handoff has no dependency on using paid Grok for production; if configured, use discovery-only adapters to propose URLs and fetch each eligible source into the ledger using existing authorization and data perimeter. Keep structured rewriters/audits grounded on verified snapshots with no search tools enabled. Enforce SDK/model capabilities at configuration and avoid committing API secrets or sending third-party licensed content to any model unless terms permit. [Web Search](https://docs.x.ai/developers/tools/web-search), [X Search](https://docs.x.ai/developers/tools/x-search), [Citations](https://docs.x.ai/developers/tools/citations), [Structured outputs](https://docs.x.ai/developers/model-capabilities/text/structured-outputs)

### Inferences

- Add thin `Provider` ports for `getSchedule`, `getEventSnapshot`, `getChanges`, and `getHeadlines`, with capability flags and explicit contract scope. Keep `fixture`, manual evidence entry, RSS-as-discovery and one selected commercial adapter initially. Persist fetch cursor/ETag/Last-Modified, source timestamps and upstream version/schema, legal retention class, UTC `collectedAt`, and hash of each lawful snapshot. On full source terms, retain licensed payloads in private store; for link-only discovery retain URL, timestamps, title and allowed metadata, with an operator evidence entry and exact evidence locator. Re-run from snapshots without touching the network. Deduplicate wire syndication by byline/agency/origin and normalize league/season/team/player/provider IDs. A canonical event ID plus opponent/home-away, UTC start, season/competition, and explicit identity mapping prevents cross-game merges. Do not use text similarity as lone identity check.
- Build stable timelines including scheduled/postponed/suspended/live/final/official/changed, home vs away, score at every play, clock or inning/half/out, participation certainty, timestamps/version and correction links. Poll schedules and approved editorial feeds at 10–20 minute intervals during slate, following provider terms/quotas and TTL, with bounded retries, backoff, `429` handling and per-provider output freshness. Reconcile after late games close and near lock; pull vendor change logs and replay past 3–4 days when available. For versioned changes, invalidate only dependent claims and scenes. No odds or live simulated gameplay in v1. Detect duplicate delivery and out-of-order correction by ID/version; fixtures should cover deletions and home-away reversed scores. [SportsDataIO corrections integration advice](https://sportsdata.io/help/sports-data-integration-guide), [NBA Daily Change Log](https://developer.sportradar.com/basketball/reference/nba-daily-change-log)
- Suggested data contracts `SourceSnapshot`, `CanonicalEvent`, `EventVersion`, `EntityMap`, `CandidateStory`, `Claim`, `ClaimSupport`, `RundownRevision`, `ScriptBlock`, `Correction`. A `Claim` includes `id`, `storyId`, `eventId`, `kind`, entity IDs, literal and typed value/unit, period/event clock, `asOf`, `status`, source evidence IDs, span/table row/event pointer, origin group, deterministically computed transform/version if derived, and human sign-off ID when required. Use `ClaimSupport` to distinguish supporting vs contradictory records and whether one is superseded. A `ScriptBlock` and graphic scene refer to claims by ID with stable per-revision hashes. Require exact equality for `winnerScore`, leader, game state and event timing, context-aware ranges/window/key tolerances for legitimate derived rounding, official canonical status for material figures, and a conflict disposition. Never let a number be deemed correct just because it occurs in the story text with another subject or game. Give long-term archive and cleanup access only to admin/editor.
- Briefing path. Generate 5–8 deduplicated pitches, select 2–4 by default after evidence gates, show why ranked with publication significance (stakes and consequence 0–4), novelty/turning point (0–3), freshness (0–2), and clarity (0–1). Visual availability is editorial tie-breaker only. Pass candidate slate to Isaac including what happened, why it matters, strongest evidence, remaining disputes, available clips/graphic fallbacks, and one suggested question for analysis. Lead with specific verified event. Make original comparisons against licensed baseline or historical data with the denominator, time period, definition and caveats visible. Outline `development → supported sequence → stakes → tomorrow/watch for → Isaac’s analysis`; short games convert to concise roundups. A thin day can ship a short verified roundup or wait. No padded segment targets. If an asset or speculative point fails its gate, drop or explicitly replace it rather than inventing facts or letting a model patch evidence.
- Improve editorial UI via direct review and chat action diffs showing story inclusion/order, angle, fact evidence, and take provenance. Keep attributed takes verbatim or save Isaac's explicit acceptance of paraphrase. Add source lineage, timestamp, clip playback bounds, editable claims/strong correction flag, lock and reopen controls, and last valid preview. Separate confirmed facts/analysis/forecast visually and in audio wording. Human sign-off during the initial shadow launch and for high-risk/contested stories makes the 08:00 automation an automatic release of an approved valid revision. Once policy matures, routine low-risk editions may follow owner-approved rule-based release, with a labeled state and no silent override of withheld claims.
- Suggested tests and release metrics: 30 editorial fixtures from at least 7 distinct simulated slates (big night, thin news day, rumors, data outage, late West Coast finish and correction), exact verification for 100% of material game facts/displayed numbers and 100% cited factual blocks, zero wrong team, winner, score or synthetic footage leakage, and reject each high-risk counterexample. Blind-review 3–5 pilots with 1–5 grading for accuracy, original analysis, structure, usefulness of visuals, and listening quality; launch threshold ≥4/5 average with no accuracy failure. Track publish success by 08:00, holds with reason, percent of fact/asset records complete, edit delta rerender time, and actual compute/provider spend per episode. Content KPI experiment: monitor baseline-normalized first-30-second retention and average percentage viewed for comparable 5–10 episode cohorts. These are recommended quality targets, not proved vendor claims.

### Gaps

- No entitlement, API access, actual wire latency, quote-transcription assets, legal interpretation, or editorial agreement were obtained in this plan. Confirm which approved source permits archiving exact text versus bounded quote/excerpt, and how to expose public correction notes. Real latency and costs require shadow measurement. A single vendor's documentation disagreement on cache interval further supports testing with actual contracted feeds.

## What should happen between overnight ingest and air?

### Takeaway

Keep the midnight Central rundown and 8 a.m. Central cron promise. A private staged video, confirmed processed before release, enables an actual public air time instead of commencing the initial upload at 08:00. Make late edits, stale/missed editions, and corrections explicit states.

### Cited Findings

- Current `desk.tick()` uses `Intl.DateTimeFormat` with `SPORTS_TIMEZONE` and hourly boundaries; an episode marked `ready` and current is uploadable in the 08:00–08:59 window, and resumable session markers prevent unsafe duplicate retry. `render` is versioned but upload success is not proof of public playback. [Edition lifecycle](../../server/sports/desk.mjs), [YouTube adapter](../../server/sports/youtube.mjs), [Host cron](../../deploy/sports.crontab)
- YouTube `status.publishAt` schedules private, never-published videos; past times publish immediately, and `videos.update` requires `privacyStatus=private` along with `publishAt`. Owner-authorized `videos.list(...part=processingDetails)` distinguishes processed from merely uploaded. When updating a part, omission of a previously set property can clear it, so preserve intended status through an explicit tested patch. Confirm whether existing upload-only scope suffices for the new API operations and request narrow additional rights if required. [YouTube video resource](https://developers.google.com/youtube/data/reference/rest/v3/videos), [YouTube processing guide](https://developers.google.com/youtube/data/guides/implementation/videos), [YouTube update](https://developers.google.com/youtube/v3/docs/videos/update)

### Inferences

- Suggested provisional Central timings: rolling retrieval, `00:00` snapshot and `00:05–00:20` pitch pack, late-game/delayed-data refresh, initial private local preview even before Isaac is online, `06:45` fact reconcile, `07:15` editable cutoff for material changes, `07:30` private stage target, `07:50` armed-release target after processing checks, `08:00` scheduled release/cron reconciliation, then verify actual playback status. Confirm host render + upload time at 95th percentile with 3–6 minute pilot videos and move editorial cutoff earlier as needed. Initially use no scheduled public release while in shadow. At 08:00 release eligible content only; hold past deadline if no valid package and surface a notification with role/action. Retry does not silently post yesterday or go public using a past `publishAt`. Coordinate exact timings with Isaac. When a correction arrives after a candidate has been armed, disarm private candidate before replacement; verify disarm response. Never arm two candidates for the same edition. If disarm result is uncertain, pause replacement release and escalate for Studio reconciliation.
- Key durable jobs by `(editionDate, rundownRevision, packageHash)` and persist private upload ID, processing status, approval snapshot, exact rights and evidence policy version, `scheduledAt`, actual verification and correction info. Claim correction expires affected revision before rendering, promotion uses compare-and-swap over accepted revision and latest rights check. Keep correction as explicit change set. If material error discovered after publishing, document publicly with a dated description/pinned correction plus next show as appropriate; if content itself materially misleads use channel-owner decision to unlist and replace with a duly cleared video, since the video binary itself is immutable. Minor non-material correction path may use approved text update. Never silently reupload when identity uncertain.
- Mock publishing tests should cover spring/fall DST, approved/scope-expired package, 07:49 edit with previous stage armed, worker restarts mid-private upload, processing still pending at 08:00, incorrect stale grant/wrong territory, duplicate cron ticks, failed disarm, acceptance with lost response, after-air corrections, and exact one public candidate. Allow publisher API stub and optional private-channel pilot gated on owner credentials and approval. Preserve public sandbox as visibly inactive until release criteria fulfilled.

### Gaps

- Real YouTube project scopes and private processing latency have not been exercised. A configured owner account must validate local OAuth setup and Google authorization requirements. Agree whether default miss means hold and revise or publishing late only with explicit editorial direction; preserve the current schedule until the new release mode is verified.
